#### 2. Taro框架介绍（25分钟）

**Taro是什么**
- Taro 是由京东凹凸实验室开源的多端开发解决方案
- 使用 React/Vue 语法编写代码，编译后可运行在多端
- 支持：微信小程序、支付宝小程序、百度小程序、抖音小程序、H5、React Native 等
- 命名来源：《超级马里奥》中的角色 Taro（太郎）

**Taro 发展历程**
- Taro 1.x：基于 React 语法，小程序端编译方案
- Taro 2.x：优化编译性能，增加更多平台支持
- Taro 3.x：重写架构，支持 React/Vue 双语法，性能大幅提升
- Taro 4.x：全面拥抱 React 18，支持小程序 2.0，性能持续优化

**Taro 核心架构**
```
┌─────────────────────────────────────┐
│          业务代码（React/Vue）       │
└─────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────┐
│         Taro 编译系统               │
│  ┌─────────┐  ┌─────────┐         │
│  │  语法解析│  │  AST转换 │         │
│  └─────────┘  └─────────┘         │
│  ┌─────────┐  ┌─────────┐         │
│  │  代码生成│  │  平台适配 │         │
│  └─────────┘  └─────────┘         │
└─────────────────────────────────────┘
                    │
       ┌────────────┼────────────┐
       ▼            ▼            ▼
  微信小程序    支付宝小程序    H5 / RN
```

**Taro 项目结构**
```
├── src/
│   ├── pages/          // 页面目录
│   │   └── index/
│   │       ├── index.tsx    // 页面组件
│   │       └── index.config.ts  // 页面配置
│   ├── app.tsx          // 应用入口
│   ├── app.config.ts    // 全局配置
│   └── app.less         // 全局样式
├── config/
│   ├── dev.ts           // 开发配置
│   ├── prod.ts          // 生产配置
│   └── index.ts         // 基础配置
├── package.json
└── tsconfig.json
```

**Taro 页面示例**
```tsx
import { useState } from 'react'
import { View, Text, Button } from '@tarojs/components'
import './index.less'

export default function Index() {
  const [count, setCount] = useState(0)

  const handleClick = () => {
    setCount(count + 1)
  }

  return (
    <View className='container'>
      <Text className='title'>Hello Taro</Text>
      <Text className='count'>计数：{count}</Text>
      <Button onClick={handleClick}>+1</Button>
    </View>
  )
}
```

**Taro 路由与生命周期**
- 路由：使用 Taro.navigateTo / Taro.redirectTo 等
- 生命周期：useLoad、useShow、useReady 等 Hooks
- 跨端一致性：API 在各端保持统一调用方式

**多端适配方案**
- 平台判断：Taro.getEnv() 获取当前环境
- 条件编译：使用 process.env.TARO_ENV
- 样式适配：使用 pxtransform 进行单位转换

```typescript
// 条件编译
if (process.env.TARO_ENV === 'weapp') {
  // 微信小程序特有逻辑
} else if (process.env.TARO_ENV === 'alipay') {
  // 支付宝小程序特有逻辑
}
```

#### 3. Taro vs UniApp 对比分析（25分钟）

**UniApp 简介**
- DCloud 推出的跨端框架
- 基于 Vue.js 语法
- 支持更多平台（含 App 端）
- 生态丰富，插件市场活跃

**核心技术对比**

| 对比维度 | Taro | UniApp |
|---------|------|--------|
| 开发语法 | React / Vue | Vue（主）/ React（实验） |
| 底层原理 | 编译时 + 运行时 | 编译时转换 |
| 小程序支持 | 微信、支付宝、百度、抖音、QQ等 | 微信、支付宝、百度、抖音、QQ等更多 |
| App端支持 | React Native | 自研引擎（5+ App / uni-app x） |
| H5支持 | 支持 | 支持 |
| 性能表现 | 小程序端优秀 | 小程序端良好 |
| 学习曲线 | React用户上手快 | Vue用户上手快 |
| 生态丰富度 | 中等 | 高（插件市场） |
| 社区活跃度 | 高 | 高 |
| 企业背书 | 京东 | DCloud |

**技术实现差异**

**Taro 方案**
- 编译时：将 React/Vue 代码编译为小程序原生代码
- 运行时：提供统一的运行时框架，处理差异
- 优势：灵活性高，可支持复杂语法
- 劣势：包体积相对较大

**UniApp 方案**
- 编译时：直接转换为各平台原生代码
- 运行时：轻量运行时，主要处理 API 差异
- 优势：性能好，包体积小
- 劣势：语法限制较多

**适用场景对比**

**选择 Taro 的场景**
- 团队熟悉 React 技术栈
- 项目复杂度高，需要更强的工程化能力
- 未来可能向 React Native 拓展
- 对代码质量和可维护性要求高

**选择 UniApp 的场景**
- 团队熟悉 Vue 技术栈
- 需要快速开发、生态插件丰富
- 需要支持更多小众平台
- 对 App 端性能要求高

**选型决策流程图**
```
开始
  │
  ├─ 团队技术栈？
  │   ├─ React → 优先 Taro
  │   └─ Vue → 优先 UniApp
  │
  ├─ 目标平台？
  │   ├─ 仅主流小程序 → 两者皆可
  │   ├─ 需App端 + 小程序 → UniApp（更成熟）
  │   └─ 需RN端 → Taro
  │
  └─ 项目复杂度？
      ├─ 简单工具类 → 两者皆可
      └─ 复杂业务 → Taro（React 生态更强）
```

**实际案例**
- Taro：京东购物小程序、京东到家、美图秀秀小程序
- UniApp：unicloud、众多中小商家小程序

### 第二学时：AI辅助开发与课程思政

#### 4. AI工具辅助小程序开发（20分钟）

**AI辅助开发现状**
- AI编程工具快速发展：GitHub Copilot、Cursor、TRAE等
- 从代码补全到代码生成，从辅助到协作
- 提升开发效率，降低入门门槛
- 改变开发模式：从"从零写"到"生成+修改"

**TRAE 介绍**
- 国产 AI 编程助手
- 支持多种编程语言和框架
- 集成代码生成、重构、解释、调试等功能
- 支持上下文理解，可基于项目生成代码
- 特别适合小程序、前端等快速开发场景

**使用 TRAE 生成小程序页面的流程**
1. 明确需求：页面功能、布局、交互
2. 编写 Prompt：清晰描述需求
3. 生成代码：让 TRAE 生成初始代码
4. 审查调整：检查代码质量，调整优化
5. 运行调试：在开发者工具中调试

**Prompt 编写技巧**
- 明确框架：指定微信小程序原生 / Taro / UniApp
- 描述功能：页面包含哪些元素和功能
- 指定样式：风格、配色、布局方式
- 说明数据：数据结构、模拟数据
- 要求规范：代码风格、注释要求

**案例演示：生成商品列表页**

**Prompt 示例**：
```
请帮我生成一个微信小程序的商品列表页面，要求：
1. 使用原生小程序语法（WXML + WXSS + JS）
2. 顶部有搜索框和分类标签
3. 商品列表使用瀑布流布局，每行两个商品
4. 每个商品卡片包含：商品图片、标题、价格、销量
5. 使用模拟数据，至少10个商品
6. 底部有"加载更多"按钮
7. 整体风格简洁现代，主色调为橙色
```

**生成结果审查要点**
- 代码结构是否清晰
- 命名是否规范
- 性能是否考虑（如wx:key）
- 是否符合小程序最佳实践
- 是否有安全隐患

**AI生成代码的优化策略**
- 补充边界条件处理
- 优化性能（减少setData、使用虚拟列表）
- 增加错误处理
- 完善用户体验（加载状态、空状态）
- 代码规范统一

**AI辅助开发的正确姿势**
- AI是助手，不是替代者
- 理解生成的代码，知其然知其所以然
- 保持代码审查的习惯
- 持续学习基础，不依赖AI
- 用AI解决重复劳动，把精力放在创新上

B. 阿里巴巴
C. 京东
D. 字节跳动

**正确答案**：C
**答案解释**：Taro是由京东凹凸实验室（JD O2O）开源的多端开发框架，命名来源于《超级马里奥》中的角色Taro（太郎）。

**第2题【单选】**：以下关于Taro和UniApp的说法，哪项是正确的？
A. Taro只支持React语法，UniApp只支持Vue语法
B. Taro支持React和Vue双语法，UniApp以Vue为主
C. Taro和UniApp都只能开发小程序，不能开发App
D. Taro和UniApp都是腾讯推出的开发框架

**正确答案**：B
**答案解释**：Taro从3.x版本开始支持React和Vue双语法；UniApp以Vue语法为主，React支持处于实验阶段。两者都支持多端开发，包括小程序、H5和App。

**第3题【单选】**：在Taro中，用于判断当前运行环境的变量是？
A. Taro.env
B. process.env.NODE_ENV
C. process.env.TARO_ENV
D. Taro.platform

**正确答案**：C
**答案解释**：process.env.TARO_ENV用于判断当前编译的目标平台，如weapp（微信小程序）、alipay（支付宝小程序）、h5等，可用于条件编译和平台差异处理。

**第4题【单选】**：使用AI工具生成代码时，以下哪种做法最合理？
A. 完全信任AI生成的代码，直接上线使用
B. 让AI生成代码后，不做任何修改直接提交
C. 理解并审查AI生成的代码，根据实际需求调整优化
D. 只让AI生成注释，代码完全自己写

**正确答案**：C
**答案解释**：AI是辅助工具，生成的代码需要开发者理解和审查，确保代码质量、安全性和业务逻辑正确性。完全信任AI或完全不用AI都不是最佳实践。

**第7题【多选】**：以下哪些属于AI辅助编程工具？
A. TRAE
B. GitHub Copilot
C. Cursor
D. 微信开发者工具

**正确答案**：A、B、C
**答案解释**：TRAE、GitHub Copilot、Cursor都是AI辅助编程工具，提供代码生成、补全、重构等功能。微信开发者工具是小程序官方开发IDE，不是AI编程工具。

**第8题【多选】**：在编写让AI生成小程序代码的Prompt时，应该包含哪些要素？
A. 使用的框架或技术栈

C. 样式风格和配色要求
D. 数据结构或模拟数据

**正确答案**：A、B、C、D
**答案解释**：编写高质量的Prompt是获得满意代码的关键，应包含：技术栈指定（如原生小程序/Taro/UniApp）、功能描述、样式要求、数据结构等，越详细生成的代码越符合预期。

D. 乡村振兴助农

**正确答案**：A、B、C、D
**答案解释**：小程序因其轻量、传播快、门槛低的特点，在公益领域有广泛应用，包括公益捐赠、寻人、无障碍服务、乡村振兴等多个方面，体现了技术服务社会的价值。

**第10题【多选】**：关于"技术服务社会"，以下理解正确的是？
A. 技术的价值在于解决实际问题、改善人们生活
B. 软件工程师有责任用专业能力为社会做贡献
C. 科技向善是技术发展的正确方向
D. 大学生只需学好技术，社会责任是工作以后的事

**正确答案**：A、B、C
**答案解释**：技术的本质是服务人类，软件工程师应具备社会责任感，践行科技向善。大学生在学习阶段就应树立正确的技术价值观，关注社会需求，而不是等到工作以后。
