# CKGDT 课程资源包审核报告

审核对象：`D:\FlutterProjects\knowledge_graph_app\data\CKGDT`  
审核时间：2026-07-03  
审核目标：确认 CKGDT 是否可作为平台内置演示课程，在系统启动后自动加载，并支撑教师、学生、管理员、智能体、技能、达成、试卷分析、归档等功能演示。

## 一、总体结论

`data\CKGDT` 已经具备较完整的课程资源包雏形，覆盖大纲、进度、理论、课件、实验、考核、达成、归档、视频、用户、项目、配置和智能体说明等内容。作为“课程知识图谱与数字孪生平台”演示课程，资源主题统一，数量充足，能够支撑课堂演示和平台化样例说明。

但当前还不能认定为“启动系统后自动加载并演示所有功能”。原因是：系统数据库只默认创建并激活 `ckgdt` 课程记录，尚未把 `data\CKGDT` 中的配置、题库、实验、归档、用户、图谱、达成等资源自动导入数据库；Flutter assets 也只注册了部分目录，`配置/大纲/进度/用户/项目/输出/文档` 等关键目录没有进入打包清单。换言之：课程记录能默认存在，但课程资源包没有形成完整的启动加载链路。

当前状态建议评定为：**资源包内容较完整，自动加载链路不完整，演示能力为“部分可用”，尚未达到平台内置示范课程的最终要求。**

## 三、启动自动加载审核

### 已具备

1. `CourseContextService` 默认课程 ID 为 `ckgdt`，默认课程名为“课程知识图谱与数字孪生”。
2. `DatabaseHelper._migrateToV15` 会在没有激活课程时插入并激活 `ckgdt` 课程。
3. `CourseAssetResolver` 已具备按当前课程 ID 解析 `data/{courseId}/{category}/...` 的能力。
4. `pubspec.yaml` 已注册部分 CKGDT 资源目录，包括：`考核`、`实验/实验教程`、`实验/报告模板`、`图谱`、`理论`、`课件`、`视频`、`达成`、`归档`各阶段。

### 不足

1. **没有发现启动时导入 `data\CKGDT\配置\manifest.json` 或 `course_gen_input.json` 的统一加载服务。**  
   目前默认课程记录和课程资源包是分离的。启动后能有 `ckgdt` 课程，但不会自动把 CKGDT 的章节、题库、实验、用户、图谱、归档材料、达成配置写入数据库。

2. **`CourseAssetResolver` 使用范围很窄。**  
   搜索结果显示它主要被考核材料页和考核智能体使用。理论、实验、学习、图谱、归档、达成、技能中心等模块并没有统一通过该解析器读取 `data\CKGDT`。

3. **打包清单已补齐。**  
   本轮已在 `pubspec.yaml` 注册以下关键目录：
   - `data/CKGDT/配置/`
   - `data/CKGDT/大纲/`
   - `data/CKGDT/进度/`
   - `data/CKGDT/用户/`
   - `data/CKGDT/项目/`
   - `data/CKGDT/文档/`
   - `data/CKGDT/实验/实验指导/`
   - `data/CKGDT/实验/平台技术栈/`
   - `data/CKGDT/输出/`

4. **默认课程章节与 CKGDT 配置不一致。**  
   `CourseContextService.defaultCourseChapters` 和数据库默认课程记录是 6 章；`data\CKGDT\配置\chapters.json` 是 8 章。系统启动后若只依赖数据库默认课程，会展示 6 章，不会自动采用 CKGDT 资源包的 8 章结构。

5. **课程名称存在不一致。**  
   资源包中常用“课程知识图谱与数字孪生平台”，数据库默认课程名为“课程知识图谱与数字孪生”。课程 ID 都是 `ckgdt`，路径解析影响不大，但报告、达成、归档、课程管理显示可能出现名称不一致。

## 四、功能演示覆盖度

### 教师端

资源包可支撑教师端演示的内容较多：

- 大纲、进度、课件、理论资料齐全；
- 实验任务、实验教程、报告模板齐全；
- 考核方案和考核报告模板齐全；
- 达成度方案和记录模板齐全；
- 四阶段归档材料齐全；
- 智能体和技能说明文档较完整。

主要风险是这些资源多数仍是文件，不一定进入教师端数据库表。例如实验任务、题库、课程资源、归档文档、达成目标、课程目标映射等，需要导入服务才能在页面中直接出现。

### 学生端

理论、测验、作业、实验教程、报告模板具备演示内容。  
但用户名单、班级成员、学习记录、测验题库、实验任务、学习路径等没有确认会从 `data\CKGDT` 自动写入数据库，因此学生登录后未必能看到完整学习任务。

### 管理员端

`用户` 目录包含教师/管理员名单和学生名单 Excel，`配置\roles.json` 包含角色权限说明。  
但目前未确认系统启动会导入这些 Excel 到 `users/classes/class_members` 表。管理员演示可能需要手动导入或依赖旧数据库种子。

### 图谱与数字孪生

`图谱` 目录仅有 2 个 Markdown 图谱文件，而课程配置为 8 章。作为平台演示，图谱覆盖明显不足。数字孪生配置在 `course_settings.json` 中存在，但没有确认其画像维度、器官隐喻、风险阈值会被启动流程读取。

### 达成与试卷分析

`达成` 目录包含达成度报告、评价方案和成绩记录模板，资源方向正确。  
近期“试卷分析”已独立 Tab，并补齐课程关联、题目满分、统计、PDF、签名等闭环，但 CKGDT 资源包中暂未看到专门的试卷分析样例数据。若要演示该功能，建议增加：

- `data/CKGDT/达成/试卷分析样例.ini`
- `data/CKGDT/达成/试卷分析样例.pdf` 或 Markdown 说明
- 与当前课程目标对应的试题满分、学生成绩样例

## 六、平台化一致性

`data` 目录中同时存在旧版通用目录、`MAD`、`SEB`、`CKGDT`。从平台化角度看，CKGDT 的目录结构已经比旧版更接近课程包：

```text
data/{courseId}/配置
data/{courseId}/大纲
data/{courseId}/进度
data/{courseId}/理论
data/{courseId}/课件
data/{courseId}/实验
data/{courseId}/考核
data/{courseId}/达成
data/{courseId}/归档
data/{courseId}/用户
data/{courseId}/项目
```

但系统代码还没有完全围绕这个规范收敛。当前多数模块仍混合使用：

- 数据库种子；
- `assets/` 固定资源；
- `data/归档` 旧路径；
- `data/达成` 旧路径；
- 局部 `CourseAssetResolver`；
- 用户运行目录中的外部文件。

因此 CKGDT 目录“结构上适合平台化”，但“代码加载机制尚未完全平台化”。

## 七、阻断项

1. **缺统一课程包加载器。**  
   需要 `CoursePackageLoader` 或类似服务读取 `data/{courseId}/配置/manifest.json`，按 `course_gen_input.json` 将课程包写入数据库。

2. **缺启动时自动导入。**  
   应在数据库初始化或首页启动阶段检查 `ckgdt` 是否已导入，未导入则执行一次幂等导入。

3. **assets 注册已完成，仍需统一加载入口。**  
   发布包已包含 `配置/大纲/进度/用户/项目/文档/输出/实验指导/平台技术栈` 等目录，但运行时仍需要统一课程包加载器把这些资源写入数据库或提供页面级读取。

4. **章节数不一致。**  
   数据库默认 6 章，资源包 8 章，需统一为 8 章。

5. **图谱资源不足。**  
   当前 2 个图谱文件不足以演示 8 章课程图谱、课程图谱、学习图谱、达成图谱和数字孪生可视化。

6. **缺试卷分析样例。**  
   试卷分析功能已增强，但 CKGDT 包内缺可直接导入的试卷分析样例数据。

7. **归档原始格式不足。**  
   若要求展示“保留 Word/Excel/PDF 原件格式”，CKGDT 归档目录需要补充原始格式样例。

## 八、建议整改方案

### 第一优先级：确保启动可自动演示

1. `pubspec.yaml` 目录注册已完成，后续需持续保持课程包目录规范：
   - `data/CKGDT/配置/`
   - `data/CKGDT/大纲/`
   - `data/CKGDT/进度/`
   - `data/CKGDT/用户/`
   - `data/CKGDT/项目/`
   - `data/CKGDT/文档/`
   - `data/CKGDT/实验/实验指导/`
   - `data/CKGDT/实验/平台技术栈/`
   - `data/CKGDT/输出/`

2. 新增课程包加载服务：
   - 读取 `manifest.json`；
   - 创建/更新 `courses`；
   - 写入章节；
   - 写入题库、实验任务、资源文件、归档文档、达成目标；
   - 导入用户、班级和分组样例；
   - 标记导入版本，避免每次启动重复写入。

3. 启动时默认加载 `ckgdt`：
   - 若无 active course，激活 `ckgdt`；
   - 若 `ckgdt` 资源包未导入，执行一次导入；
   - 若资源包版本更新，执行增量更新。

### 第二优先级：完善全功能演示

1. 补齐 8 章图谱，至少每章 1 个图谱文件。
2. 增加试卷分析样例数据。
3. 增加 CKGDT 达成度样例成绩和课程目标映射。
4. 增加 Word/Excel/PDF 原始归档材料样例。
5. 增加学生端学习记录、测验结果、实验提交、作品展示样例。

### 第三优先级：统一平台化路径

1. 推广 `CourseAssetResolver` 到理论、实验、图谱、归档、达成、技能中心。
2. 将旧路径 `data/归档`、`data/达成`、`data/考核` 逐步改为 `data/{courseId}/...` 优先。
3. 对外部课程如 `MAD`、`SEB` 使用同一 `manifest.json + course_gen_input.json` 规范。

## 九、结论

`data\CKGDT` 已经是一个内容丰富、方向正确的 CKGDT 演示课程资源包。它适合作为系统平台化后的内置示范课程，但目前还只是“资源目录完成度较高”，不是“系统启动即可完整加载的课程包”。

要达到目标，需要补齐三件事：

1. 完整 assets 注册或外部资源复制机制；
2. 启动时幂等导入 `data\CKGDT` 到数据库；
3. 将各功能模块统一接入课程包路径和课程 ID。

整改完成后，系统才能真正做到：启动后自动加载 CKGDT，作为演示课程展示所有功能，同时又能切换到《移动应用开发》《软件工程基础》等通用课程。
